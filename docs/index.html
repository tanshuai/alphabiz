Framework

Build your own branded app

This repository is Alphabiz's distribution point and its "build your own branded app" framework. The application core (renderer and main process) is built from the upstream Alphabiz application repository and shipped here as production bundles with each release; everything needed to brand, package and test an app on that core lives here.

Clone your fork with git (a source ZIP will not build), edit developer/app.js and the assets, then run the four commands from the repository root. Before you ship, work through the fork checklist: update repository, versionsUrl, externalI18n, take-down admins, recommended channels and community links all default to Alphabiz's own values.

Build guide →

  1. 1
    yarn

    Tooling and the custom Electron 21.3.3 runtime.

  2. 2
    yarn unpackaged

    The application bundle's dependencies — vendored, no registry token.

  3. 3
    yarn packager

    Assembles the app under dist/electron/<Name>-<platform>-<arch>.

  4. 4
    yarn make

    Installers land in out/installers/<version>/.

Windows: an APPX needs a signing certificate supplied through the ALPHABIZ_APPX_* variables; for unsigned EXE and MSI installers run yarn make:squirrel && yarn make:msi instead. If you change version in package.json, set the same value as newTagName in release.json and keep targetTagName at main.

What is in the repository

dist/
Production application bundles: the Electron main process (dist/electron/UnPackaged/) and the SPA (dist/spa/).
developer/
Branding and behaviour: app.js, icons and platform assets, update channels, take-down policy, dynamic config, terms of service.
build-scripts/
Installer builds: Squirrel EXE, MSI (WiX), APPX, DMG, DEB, Snap.
vendor/
Vendored first-party packages (@zeeis/alphabiz-account, @zeeis/alphabiz-libdb) so a fork installs without a registry token.
i18n/
External translations, loaded by installed apps at runtime from main.
test/
Playwright, Cypress and Jest end-to-end and release tests.
scripts/
Credential scanning, dependency regression tests and the release version contract run by CI.
docs/
Build and customization guides in English and 中文.

Engineering standards

Maintenance and release standards

August 2026 brought 22 merged pull requests: security hardening, dependency fixes, least-privilege CI with CodeQL, a release version contract and vendored first-party packages. CI and CodeQL run on every push and pull request to main.

Release quality standards

Applied to every tagged release.

  1. 1
    Security

    No signing keys or credential material in the repository; credential scanning, CodeQL and least-privilege automation run on every change.

  2. 2
    Repeatable builds

    A clean git clone installs its dependencies and builds through the documented path, with the first-party packages vendored in the repository.

  3. 3
    Quality

    Required CI, static analysis and platform smoke tests pass on the release candidate.

  4. 4
    Release integrity

    Artifacts, .sha checksums, build provenance and signing expectations are explicit and independently checkable.
